| 要望 | 明示された条件 | 本資料での対応 |

## 2. スキル定義と武器への割当を分ける

### 2.1 データの責務

| 部品 | 保持する内容 | 分ける理由 |
| --- | --- | --- |
| スキル定義 | SkillID、名前、通常/ULT、基準CD、効果、対象、始動、硬直、自動条件。 | 同じスキルを別武器へ割り当てても定義を複製しない。 |
| 武器種・生成テンプレート | 武器種、基準パラメータ、生成の許容範囲、適性。 | 武器種ごとの特徴を保ち、無制約な乱数生成を避ける。 |
| 武器とスキルの適性 | SkillIDと武器種、許可する割当欄。 | 多対多の関係を明示し、不適合な自動割当を検出する。 |
| 生成武器 | 武器ID、生成時パラメータ、S1/S2/ULTのSkillID、seed、生成器・定義の版。 | 同じ武器を再読込できる。後から定義が変わっても保存値を勝手に再抽選しない。 |
| 戦闘内の状態 | 使用者、武器ID、実際の割当欄、SkillID、CD進行、始動・硬直、使用履歴。 | 共有するSkillIDを別の冒険者が使っても、CDを全員で共有しない。 |

例としてSK-SW-1-05「灯火の手当」は、剣を主な提案区分としているが、同じ定義を槍・槌・杖にも割当可能とする案。槍用の同名別IDは作らない。主な提案区分と、実際に割り当てられた武器・欄を分ける。

### 2.2 割当の検証案

- S1・S2は通常スキル、ULTはアルティメットだけを受け付ける。
- 通常スキルの提案区分S1/S2は一覧を整理する区分。適性がある通常スキルを実際のS1/S2どちらへ割り当てるかは別の関係として扱う。
- 同じ武器内で同一SkillIDを2欄へ重複割当しない案とする。上限2を同一能力の複製で使い、CDや直接加護を二重適用する問題を避ける。
- 空欄は「未設定」として保持し、ダミーの0CDスキルを作らない。
- 別武器に同じSkillIDがあっても、許可された適性関係があれば有効。

重複割当禁止や具体的な適性一覧は候補ルールであり、今回の上限・多対多という明示条件そのものとは分ける。

## 3. 自動発動の共通処理案

### 3.1 発動の条件

発動者が生存し、行動可能で、対象・観測・範囲・個別の自動条件を満たし、CDが完了した能力だけを候補とする。回復は生存する負傷者、弱体だけの能力は有効な弱体対象がいなければ発動しない。攻撃に付随する弱体が無効なら、攻撃だけ行う等の扱いは個別に記載する。

1. 通常攻撃・移動等の現在の行動の区切りで、自動スキル候補を評価する。
2. 優先度の大きい順、同順位は発動可能になってからの待ち時間、さらに同じならULT→S1→S2で1つだけ選ぶ案。
3. 対象と元のスキル行動IDを確定し、その時点でCDを開始する。
4. 始動後に効果を解決し、max(0.25秒、技能定義の硬直時間)は他の自動スキルを発動しない。
5. 標準では中断時にCDを返還しない。返還を行う特定加護は、対象・量・回数を明記する。

開始時は通常スキルを使用可能、ULTは基準のCDから開始する候補。開幕から使えるULTにするか等は調整対象である。手動ボタンや新しいMP・アルティメットゲージは今回追加せず、CD方式で検討する。

### 3.2 通常攻撃・スキル・誘発の区別

- 通常攻撃と元のスキル行動は別の発生元。旧UNIQUEの「通常攻撃で」という条件を、自動スキル全般へ自動拡大しない。
- 新しいスキル関連加護は、対象SkillIDまたは実際のS1/S2/ULTと、元のスキル行動を参照する。
- 同じスキルの多段命中・範囲命中・継続tickは、新しいスキル使用回数として数えない。
- 加護で生成した追撃・回復・反射・継続ダメージから、自動スキルやCD還元を再誘発しない。
- マッチ中の装備・加護構成固定は維持し、HP・Lv・一時強化・状態異常の変化による再計算と両立させる。
- 強制終了後は同じ行動IDの二重適用を防ぐ。Wave復帰のLv以外の変動リセットと、重複防止用の実行履歴は別に保持する案。

再挑戦を同じマッチとする方針は維持する。CDや使用履歴の復元・消費をどこで確定するかは既存の再挑戦境界と合わせて判断し、今回の加護だけで恒久育成・報酬を増殖させない。

## 4. スロット別ステータスとCD操作案

### 4.1 追加するパラメータ候補

S1・S2・ULTのそれぞれへ同じ形の項目を用意する。基準値は割当スキルから参照し、補正は実際の割当欄を対象とする。

| 項目 | 基準・主な用途 | 条件・候補範囲 |
| --- | --- | --- |
| 基準CD秒 | スキル定義のbaseCdSec。 | 正値。未割当欄は未設定。 |
| CD固定減算・延長秒 | 固定段階で短縮/延長。 | 減算量・延長量は非負値として別に保持。 |
| CD割合短縮・延長 | 割合段階で操作。 | 短縮0〜80%、延長0〜300%は調整候補。 |
| CD回復速度倍率 | 実効CDを割る係数。 | 0.25〜3、基準1の候補。 |
| 実効CD秒 | 補正後の待ち時間。 | 安全下限と元CD4倍の上限候補で制限。 |
| 威力倍率 | ダメージ成分。 | 基準1、0.1〜5の候補。ダメージを持たないスキルへ攻撃を新設しない。 |
| 回復倍率 | 回復成分。 | 基準1、0.1〜5の候補。HP0復帰・最大HP超過を追加しない。 |
| 弱体強度倍率 | 弱体の強さ。 | 基準1、0.1〜3の候補。持続時間とは別。 |
| 支援補正量倍率 | 味方への能力補正量。 | 基準1、0.1〜3の候補。回復量・範囲・持続とは分け、元の成分のみを強める。 |
| 効果時間倍率 | 持続時間。 | 基準1、0.25〜3の候補。個別の制御上限を維持。 |
| 効果範囲倍率 | 形状・距離。 | 基準1、0.25〜3の候補。観測や行動範囲の制約は維持。 |
| 対象上限加算 | 最大対象数を増やす。 | 0〜3の整数候補。個別の最終上限を優先。 |
| 詠唱・始動速度倍率 | 始動を早める。 | 基準1、0.5〜2の候補。0時間化しない。 |
| CD安全下限 | CD0やULT連打を防ぐ。 | 次節の式。 |

固定のCD欄を持たない能力や、効果未定のメタ加護へ数値0を代入して、発動可能と扱わない。

### 4.2 CDの計算

基準CDをB、固定減算をF減、固定延長をF増、割合短縮をP減、割合延長をP増、回復速度をVとする。通常S1/S2の下限L=max(1秒、B×10%)、ULTの下限L=max(10秒、B×25%)、上限U=B×4という候補。

1. C1=Clamp(B−F減+F増、L、U)
2. C2=Clamp(C1×(1−P減+P増)、L、U)
3. 実効CD=Clamp(C2÷V、L、U)

固定→割合→乗算の各段階で上下限を適用する既存方針と合わせる。回復速度はこの除算へ1回だけ使い、さらにゲージの速度へ掛けて二重短縮しない。

CD進行は0〜1の比率を保持し、時間経過ごとに経過時間÷実効CDを加える案。補正が変わっても進行を0へ戻さない。例えばCD10秒で50%進行済みの能力が実効8秒へ変われば、残りは4秒となる。

直接CD還元は、同じ元スキル行動IDから1回だけ、残り進行量の25%まで等の安全枠を設ける候補。生成追撃や同一行動の複数命中から何度も還元せず、スキル使用をその場で再誘発しない。具体的な還元量・対象は加護表で確認する。

### 4.3 直接SkillID補正と欄別補正

- SkillID直接補正は、そのIDが別武器へ共有されても適用する。武器種条件を明記したものだけ追加制限する。
- S1/S2/ULT補正は実際の割当欄へ適用する。提案カタログの主区分へ適用するのではない。
- 同じ補正成分がID・欄の両経路で一致しても1回だけ適用する。異なる加護・異なる成分は通常の補正順でまとめる。
- 加護の整理用武器種ラベルを、書かれていない使用制限へ読み替えない。
- 威力・回復・弱体・持続へ効く条件を分け、回復だけのスキルへ威力補正を無理に当てない。

### 4.4 加護成分と計算パラメータの換算

追加加護の`*_BONUS`は倍率そのものではなく、基準1へ足す比率の差分。例えば+5%を0.05として保存し、合計後の倍率を1.05とする。Excelの「パラメータ」には49項目と、実データに存在する30キーの換算参照を載せる。換算表は別の重複入力ではない。

| 加護成分の末尾 | 計算先・扱い |
| --- | --- |
| POWER_BONUS / HEAL_BONUS | 威力/回復倍率=1＋一致する比率補正合計。 |
| DEBUFF_STRENGTH_BONUS / SUPPORT_STRENGTH_BONUS | 弱体/支援補正量倍率=1＋一致する比率補正合計。 |
| DURATION_BONUS / AREA_SIZE_BONUS | 時間/範囲寸法倍率=1＋一致する比率補正合計。範囲寸法は射程・対象数とは別。 |
| CD_FIXED_DELTA | 秒の符号付き差分。負成分の絶対値を固定減算、正成分を固定延長へ分ける。 |
| CD_REDUCTION_RATE | CD割合短縮へ加算。0.05は5%短縮。 |
| CD_RECOVERY_BONUS | CD回復速度=1＋比率補正合計。0.05は速度倍率1.05。 |
| CAST_REDUCTION_RATE | 始動時間の短縮率r。速度倍率は1/(1−r)。候補の速度0.5〜2はr=−1〜0.5に相当。 |

接頭辞S1/S2/ULTは実際の割当欄。接頭辞SKILLは独立した4番目の欄ではなく、対象SkillIDと条件に一致する能力の実割当欄へ解決する。既存の各段階の上下限を適用し、同じ成分は一度だけ計算する。

## 5. スキルに関与する追加加護150件

| 区分 | 件数・ID | 作成の狙い |
| --- | --- | --- |
| 通常 | 50、SN001〜SN050 | S1/S2/ULT共通の操作と、特定SkillIDの直接強化。 |
| 通常上位 | 50、SH001〜SH050 | 元の条件・対象SkillID・補正方式を保持した圧縮。 |
| UNIQUE | 50、SU001〜SU050 | 同じスキルでも対象・形状・分配・消費・発動タイミング等が変わる案。 |

合成は異なる2加護の各Rank IIIから1個1枠Rank I。上限III、追加通貨なし、失敗なし等の条件を維持する。追加の上位・UNIQUEには100レシピを対応させ、既存200と合わせて300を参照できる。

素材効果の条件・単位・SkillIDを落とさず、上位の数値成分は既存の2/3・1・4/3という候補規約へ合わせる。固有能力を持つSUは素材の数値継承と固有の性能予算を分ける。比較・採用・性能調整は、具体案を作成したことと区別する。

## 6. 武器の自動生成は可能か

**可能。武器種ごとのテンプレートと生成範囲を決め、その範囲でパラメータとSkillIDの組み合わせから生成する方式が適する。** 0スキル武器もあるため、武器種ごとの通常攻撃の基準は必要になる。

固定の武器表をすべて手作業で増やす代わりに、生成に使う少数のテンプレートと、スキル定義・適性・性能配分の規則を管理する。ただし「乱数で作れる」ことだけでは性能が適切と保証できないため、制限と保存方法を一緒に設計する。

### 6.1 推奨する生成の流れ

1. 武器種・テンプレート版・生成予算・seed・生成器版を決める。
2. 通常0〜2、ULT0〜1の構成を選び、適性関係からSkillIDを選ぶ。
3. 欄上限・種類・重複割当・必要対象・数値下限を検証する。
4. 選んだスキルのCD・係数・対象数・役割から、生成用の性能負担を概算する。
5. 残った性能配分と武器種の基準、seed由来の変動から通常攻撃威力・間隔・射程等を生成する。
6. 生成値・割当・seed・各版を武器の保存値として保持する。ロードのたびに再抽選しない。

生成予算は設計上の指数であり、ゲーム内通貨やMPを新設する意味ではない。スキルの係数・対象数・CDからの点数化は初期案で、回復・弱体・射線・発動条件の価値はプレイ検証で調整する。

### 6.2 比較した方式

| 方式 | 利点 | 制約・評価 |
| --- | --- | --- |
| 全武器を固定表で定義 | 個別の調整を確認しやすい。 | 多対多のスキル組み合わせが増えるほど手作業が増える。基準例としては有用。 |
| テンプレート＋制約付き自動生成 | パラメータ・SkillID・seedを再利用でき、組み合わせと再現性を両立できる。 | 生成範囲・適性・性能配分・保存版管理が必要。本案で採る方向。 |
| 条件を設けない完全乱数 | 組み合わせ数を増やしやすい。 | 不適性・極端なCD・回復対象不在等を作りやすいため採用しない候補。 |

### 6.3 生成例と計算範囲

Excelの武器生成例は5武器×6構成の30件。基礎型（0/0）、単技型（1/0）、双技型（2/0）、奥義型（0/1）、三枠型（2/1）、別武器と同じSkillIDを使う共通技能型（2/1）を載せる。

例の通常攻撃予算=max(40、生成予算−技能負担合計)。生成基礎威力=max(1、round(武器種基準威力×威力変動係数×通常攻撃予算/100))。攻撃間隔は武器種基準間隔×間隔変動係数をミリ秒相当で丸める。基準威力10・9・15・7・8等は旧装備案の入力例として使い、生成武器の固定最終値として採用しない。

通常攻撃の配分を下げて強いスキルを付けるなどの関係は計算例で見えるが、これは実際のDPS・回復量・防衛成功率の検証ではない。実装時には生成器、スキル実行、CD進行、対象選択、結果保存が必要になる。

## 8. 残る判断
