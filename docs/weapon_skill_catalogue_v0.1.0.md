## 1. 登録とスロットの読み方

すべての武器は通常スキル0〜2・アルティメット0〜1の構成を取れる。全スキルは戦闘中に条件で自動発動し、それぞれ固有CDを持つ。ULTもCD方式であり、新しいMP・ゲージ・消費資源を追加しない。

IDの1/2/Uはこの一覧を作る際の提案分類。通常スキルは、実際の武器に割り当てる際にはS1・S2のどちらへも置ける。分類S1の技能をS2へ置いても同じSkillIDを使用する。ULTはULTへだけ置ける。

原武器はスキルの発想・見せ方の分類であり、固定ジョブではない。共通適性のある同じSkillIDは、別武器でも同じCD・条件・式・効果を参照する。たとえばSK-ST-1-02「澄光の手当」は5武器すべてが同じIDを利用でき、武器ごとに回復技能を複製しない。

compatibleSlots/allowedSlotsは割当可能な位置を示すもので、同一武器のS1とS2へ同じIDを同時搭載する許可を自動的に意味しない。搭載の重複制限とスロット別CDの運用は、[共通設計](weapon_skill_system_v0.1.0.md)に従う。

## 2. 共通記号と発動・対象・制約

### 2.1 計算と対象数

- A：使用者の装備・能力値・有効補正から計算済みの攻撃値。
- R：使用者の計算済み回復力。
- H：使用者の計算済み最大HP。回復対象の最大HPの割合ではない。実回復の上限は対象自身の現在の最大HP。
- powerCoefficientは1hitに対するA係数、healCoefficientは1回の回復に対するR係数。H項・複数hit・複数tickは式と効果に明記する。
- ダメージ式は防御・耐性・会心等の共通計算へ渡す前の元スキル係数。直接HPへそのまま代入する式ではない。未確定の戦闘計算式をこの一覧で確定させない。
- 範囲はマス。円・扇・直線はこの一覧の候補形状であり、通常攻撃の射程とスキル固有射程を区別する。敵は原則として認識済みの有効対象を必要とする。
- 対象上限は1回の判定の上限。多段攻撃や固定領域は各回で上限を適用する。全hitを複数の敵へ配る技能は「全対象で共有」と式に明記する。
- 複合技能が敵と味方へ同時に作用する場合、対象欄で敵・味方の人数を分ける。使用者自身への補助効果も明記する。

攻撃属性は各スキルの効果欄に固定する。同一SkillIDを別武器へ割り当てても、定義の属性や効果をコピー変更しない。物理と魔法の複合属性計算が未確定のため、火矢等は単独の火属性魔法として提示し、武器属性をさらに重ねる新規計算を追加しない。

### 2.2 自動発動とCD

HP0・行動不能・対象不在では発動しない。各行の自動条件と対象条件を満たし、割当スロットが利用可能で、固有CDが終了していることを必要とする。条件を満たす候補が複数あるときの優先度は大きい方を優先する候補値で、同順位時の共通ルールは共通スケジューラ案へ合わせる。

表のCD・キャスト・硬直は秒単位の基準候補値。発動確定でCDを開始し、中断による返還は標準なし。キャスト中の他スキル発動禁止、完了後の共通硬直下限0.25秒、初期準備状態、CDの床・上限・回復速度との計算順は共通設計案を参照する。この表のrecoverySecが0.25秒を超える場合はその時間を使用する。

自動回復は発動前に有効な負傷者を確認する。HP満タン・HP0の対象へ空撃ちせず、対象不在なら発動前のCDを消費しない。継続回復の各回もHP満タン・HP0・範囲外を除外し、不発回を後で補填しない。

### 2.3 制約記号

各行の制約欄は次を参照する。JSONには各行の全文を持つ。

| 記号 | 制約案 |
| --- | --- |
| C0 | 新しいMP・ゲージ消費なし。元スキル行動として発動し、派生hit・継続tickから自動スキルを再発動させない。中断時CD返還なし。 |
| H0 | 生存負傷者のみ回復。HP満タン・HP0を除外し、発動前に対象がいなければ空撃ちせずCDも消費しない。回復上限は対象の最大HP。 |
| W0 | ダメージなしの弱体は、すべての弱体が無効な敵を除外。有効対象が必要数いなければ発動しない。 |
| M0 | 攻撃を伴う副次弱体は、無効な成分だけ省略し、攻撃条件が成立すれば攻撃を実行してCDを消費する。 |
| B0 | 有効な付与・解除対象がなければ発動しない。同IDの同補正を重複加算せず残時間を更新する案。 |
| T0 | 継続回復の各回でHP満タン・HP0・範囲外を除外。不発回の補填なし。固定円では各回選び直す旨を個別に記載する。 |

一度のスキルから出る複数hit・複数tick・領域判定は同じ元行動の識別を保持する。派生hitを新しいスキル発動と見なしてCDや自動発動を再開しない。加護による元行動・派生行動の変更は共通設計へ接続する。

毒・炎上の解除スキルはマッチ内の一時状態だけを対象とし、恒久的な不利を取り除く浄化アイテムの役割を置き換えない。回復スキルによるHP0の復活は追加しない。

## 5. 件数と整合性の確認

- 5武器×3提案区分×10件＝150定義。通常100件、ULT50件。
- ID・名称は全150件で一意。S1/S2分類をコピーして同じ技能を別IDへ水増ししない。
- 原武器150＋別武器45＝195関係。すべての関係が実在するSkillIDを参照する。
- 各武器に攻撃、回復、支援、弱体、複合を配置し、固定ジョブを作らない。
- 全固有CDは正値。キャスト・硬直は0以上、対象上限は正の整数。
- 通常の適性スロットはS1/S2、ULTの適性スロットはULTだけ。互換武器の配列と関係表の武器集合を一致させる。
- powerCoefficient・healCoefficient・durationSecは数値またはnull。攻撃回数・回復回数とH項は式・効果で補足する。
- スキル定義のJSONとこの一覧は同じ設計データから作成する。JSONは表計算用の一時設計資料で、ゲームへ読み込む実装データではない。

## 6. 共通設計との接続

スロットCD、CD操作の対象、同時発動の競合、通常攻撃・移動との競合、キャスト中断、スナップショット、加護が変更するhit数や対象数の上限は共通設計に従う。個別の効果が共通の上限や既存の未確定事項を勝手に上書きするものではない。

回復量・弱体量・範囲・優先度などの具体値は初期比較用の候補であり、このファイルの作成を全150件の採用決定と扱わない。既存の未確定なダメージ式・基礎能力値の関連式・属性複合計算・状態異常の重複ルールは、それぞれの案と合わせて整理する。使用者がHP0になった後の発射済み投射物・設置領域の残留や、途中再開で保存する進行状態も共通設計で定める。

今回の作成範囲は設計文書と表計算用の一時JSONに限る。ソースコード・実行データ・Issue・リリース情報は変更しない。
