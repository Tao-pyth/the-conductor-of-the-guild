# 0.4.0-dev 公的ギルドUI改修・ローカル契約

2026-10-25。正式baselineはv0.3.0。対象は現在の0.4.0-devのUI改修で、既存の判断支援・保存互換を保持する。ユーザーが採用した明るい公的ギルド・押印・フルHD基準の配置準備画面をゲーム本体へ実装する。旧0.4契約の実装済み機能は維持し、この文書はUI/表示設定/検証/ローカル配布に関する追加契約とする。

## Goal / Scope

- 白〜生成りの帳票、明るい木材、青緑、朱印、濃色の本文で、公的な冒険者ギルドを表す。共通テーマを明るくし、拠点・編成・成長・戦闘・結果の文字も読める状態を維持する。
- 配置準備は左名簿・中央地図・右配置記録の3列。名前/HP/配置状態、費用、XP購入、復帰、標的優先、開始操作を長文詳細の外へ出す。能力・技能全文は開閉/スクロールできる詳細へ置く。
- 1920×1080を論理表示の基準、1280×720のHDでも同じ構成。従来最小1000×640でも主要操作へ到達する。16:9以外は比率を維持し、地図のマスを潰さない。
- ボタンとF11でウィンドウ/全画面を切替。Escで全画面から戻れ、ウィンドウ位置/サイズを復元する。表示切替はゲームの状態・乱数・保存を変更しない。永続設定の新設はしない。
- 朱印の「出撃承認」は既存StartWaveの一操作。視覚的な押印反応を付ける場合も、追加の承認手順や開始遅延による連打受付を作らない。
- 地図は明るい配置域/経路/非配置域、座標、武器トークン、HP/選択表示、既存の複数範囲を正しく示す。装飾は配置可否を示すルールを増やさない。
- 採用画像の紋章・紙/木の面・押印の小道具等は画像アセットとして用意し、動的な本文/資源/状態を画像に焼き込まない。

## Non-Scope

ドメイン/敵/報酬/能力/射程/成長/保存形式の変更、新しい職業/機能/ステージ、精算予測、標的線、DPS、3D化、OS IME一般対応、公開、Commit/Push/PR/Tag/GitHub Releaseは対象外。既存の未コミット変更を巻き戻さない。

## Acceptance Criteria / Test Requirements

- UI-AC01: 新しい紙/木/紋章/朱印を用いた明るいテーマが実ゲームに反映され、採用画像と同じ準備3領域・情報階層が実画面で確認できる。単に暗色を明色へ変えるだけで完了しない。
- UI-AC02: 防衛と侵攻の準備で名簿選択・地図クリック・初配置・無料再配置・XP購入・復帰可否・標的優先・範囲/技能範囲・詳細の操作が従来のコマンドへつながる。選択・閲覧だけで状態/保存/乱数を変えない。
- UI-AC03: 成長対象、恒久Rank/今回Lv、拠点/マッチ資源、参考/実値、実技能枠と空枠、単位、旧判定注意、未発見合成の非公開を維持する。
- UI-AC04: 防衛/侵攻の開始は朱印の一操作で一度だけ実行できる。押印後は正しい戦闘画面へ移る。キー操作の到達性と無効状態を保持する。
- UI-AC05: FHD1920×1080、HD1280×720、従来最小1000×640でPNG・window/viewport実寸・主要領域の境界を記録し、配置候補、選択者、費用、開始操作が欠けずに到達できる。長い日本語名、詳細全文、候補多数も確認する。
- UI-AC06: 実ゲームでボタン/F11/Escによる全画面切替と復帰を確認。切替前後のゲーム状態が同一で、復帰サイズが正しい。全画面中のPNG/実寸も記録する。
- UI-AC07: 地図は正方形の16×10マスと実座標で、道上配置を許さず、範囲半径/線種・hover/再配置の位置計算が一致する。旧防衛/侵攻の挙動を変更しない。
- UI-AC08: 全192既存ドメインテストが失敗/skip0。Godot sourceとWindows配布実体の必要シナリオが終了コード0・期待マーカー一致・実行エラーなし。拠点・成長・両モード準備/戦闘/結果/再開を回帰確認。
- UI-AC09: 採用画像と新規実画面を同じ状態で比較し、重大な欠け・重なり・読めない文字・暗い残留面を修正する。生成画像の概略をゲーム数値の正本にしない。P0/P1/P2の視覚/操作課題を残したまま完了しない。
- UI-AC10: 説明文書、実際の検証記録、アセット出典、Windows ZIP/SHA256を新しい保存先へ生成し、SDK不要の配布実体を確認する。旧ローカルZIPを上書きしない。
