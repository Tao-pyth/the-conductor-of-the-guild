# 侵攻モード仕様案 — 育てた冒険者による敵陣攻略

作成日：2026-10-24。基準版：**v0.2.0**。提案対象：**v0.3.0-dev（ローカル技術検証版）**。

2026-10-25追記：本案に基づく実装・動作確認は[侵攻検証記録](invasion_verification_v0.3.0.md)を参照。本書は採用した計画を保持し、実装・検証の証拠と分ける。

## 1. この案の位置づけと目的

ユーザーが採用した「育てた冒険者で敵陣を攻略する」方向を、実装・検証に渡せる仕様案へ具体化する。今の防衛で育てた同じ冒険者を使い、前衛・遠距離攻撃・回復などの組み合わせを攻める場面でも試せることを目的とする。固定ジョブは追加しない。

以下では一つの初期案に絞る。区画数・敵性能・時間・報酬などの**調整初期値は今回の提案**であり、既存の確定仕様、正式公開済みの内容、ユーザー回答済みの値へ読み替えない。第4確認票の未回答を補完回答した扱いにしない。今回は仕様文書の作成までで、実装や公開は行わない。

| 区分 | 内容 |
| --- | --- |
| 採用された方向 | 育成済み冒険者、敵陣への侵攻、既存の自動戦闘を活用 |
| 継承する規則 | 固定ジョブなし、最大10名、最低1名で開始、Lv1〜10、持込構成固定、復帰・再挑戦・一度限りの帰還精算 |
| 侵攻用の新しい規則案 | 自動進軍、区画間準備、守備隊・設備、攻撃可能な拠点、全滅・時間切れ敗北 |
| 調整初期値 | 1ステージ3区画、各区画300秒、下記の配置・敵性能・報酬係数 |

## 2. Release Goal / Scope / Non-Scope

**Release Goal：** 既存セーブの冒険者を使い、編成→3区画の侵攻→勝敗→帰還・成長→防衛または侵攻へ再出撃、という1サイクルをローカルWindows版で確認できる。

**Scope：** モード・ステージ選択、侵攻1ステージ、区画準備、自動進軍・交戦、近接守備兵・固定砲台・門/最終拠点、勝敗、Lv/資源/復帰、結果精算、保存・再開、日本語UI、既存防衛の互換検証。

**Non-Scope：** 複数経路、自由な移動指示、手動技能、隊列の自動維持、戦闘中の追加出撃、敵陣営の操作、途中撤退、専用加護・新武器、候補台帳全件の実装、罠・召喚・ボス専用機構、オンライン、正式公開。

## 3. 体験と画面の流れ

拠点 → 防衛/侵攻とステージを選択 → 所有冒険者から遠征編成を選択 → 区画1準備 → 侵攻開始 → 区画1突破 → 区画2準備 → 区画2突破 → 区画3準備 → 最終拠点攻略 → 結果 → 帰還・恒久成長。

- 既存の冒険者Rank、能力・成長、生成済み武器、加護、HP、衰弱、次回効果を共有する。侵攻専用の別個体や別育成値は作らない。
- 同時に進行できるマッチは1件。防衛の途中から侵攻を始めず、保存済みマッチがあればその再開を優先する。
- 出撃確定前の選択画面では戻れる。確定後は開始構成を固定し、途中撤退は設けない。編成確定画面にこの条件を表示する。
- ステージ選択には区画数、報酬用Rank、敵種、制限時間と報酬初期値を表示する。初期マップは全体と全敵配置を準備中に公開し、索敵や隠し増援は設けない。

### 3.1 編成・配置

- 遠征編成は所有冒険者から1〜10名。出撃確定後は編成メンバー・装備・加護・開始時定義を変更しない。遠征外の冒険者は追加できない。
- 最初の区画で全員を出す必要はない。区画準備で編成内の未出撃者を初配置できる。各戦闘の開始にはHPがある配置済み冒険者が1名以上必要。
- 一度配置した者はそのマッチの参加者となり、以後の区画へ引き継ぐ。配置解除や、控えへ戻して回復する操作は設けない。
- 初配置費用の初期案は `min(250, 25 × (1 + floor(開始時Rank / 10)))`。費用不足・不正配置では資源を消費しない。既配置者の区画間再配置は無料。
- 区画ごとに左側の出撃マスへ配置し直せる。次区画では、直前の準備で各人に指定した出撃マスへ自動で戻し、そこから無料で再配置できる。生存者・戦闘不能者とも出撃マスの指定を保持し、復帰はその指定先を使う。初期配置は前後関係を作るが、進軍中の速度差・攻撃硬直で並びは変わる。初期版は自動で隊列を維持しない。
- 戦闘中は初配置・再配置・復帰・Lv購入・装備変更を行えない。控えが残っていても、戦闘中の配置済み部隊が全滅すれば敗北する。

### 3.2 操作と表示

| 時点 | 操作できること | 主な表示 |
| --- | --- | --- |
| 区画準備 | 配置、無料再配置、復帰、LvXP購入、Lv強化選択、攻撃優先変更、開始 | HP/Lv、参加・控え・戦闘不能、各費用、残資源、敵配置、区画報酬 |
| 戦闘中 | 冒険者選択、攻撃優先変更、一時停止、1倍/2倍 | 区画番号、残り時間、残敵数、門/拠点HP、進軍/交戦/技能動作/戦闘不能 |
| 区画突破 | 次区画の準備へ進む | 獲得マッチ資源、LvXP、HP0者、次区画の敵配置 |
| 敗北結果 | 同じ開始点から再挑戦、帰還して精算 | 敗因、最終試行の突破区画、参加者、帰還時の獲得見込み |
| 勝利結果 | 帰還して精算 | 拠点攻略、参加者、帰還時の獲得見込み |

一時停止中は表示・優先設定のみ変更可能。戦闘時間、移動、技能CD、状態異常の時間は進めない。2倍速は同じ固定更新を実時間あたり2倍実行する。

## 4. 自動進軍と戦闘

### 4.1 進軍の基準

1. 各冒険者が一本道の経路を自分の実効移動速度で進む。経路外の出撃マスは最寄りの経路点へ対応付け、同距離なら小さい経路番号を使う。まず4方向移動でその点へ合流する。合流までは出撃マス、合流後は経路上の自分の進行位置を行軍点・行動中心とする。味方・敵・戦闘不能者の占有による通行待ちは設けない。交戦は攻撃と射程で表現する。
2. 次の進軍目標は、残っている敵のうち最も入口寄りの初期配置に対応する経路上の点とする。初期配置から最短の経路点へ対応付け、同距離なら小さい経路番号を採用する。全員が無視した残敵を置き去りにして終点で停止する状態を防ぐ。
3. 各冒険者の行軍点は経路上の自分の進行位置とする。交戦開始でその地点を一時的な行動中心に固定する。行動半径の初期値は3マス。
4. 警戒範囲の初期値は4マス。標的候補は「生存する相手」「警戒範囲内」「行動範囲内に、その相手へ攻撃できる到達可能な位置がある」の全条件を満たすもの。視認だけで進軍を止めない。
5. 候補を得たら武器の実効射程に入れる位置まで接近して自動攻撃・自動技能を使う。攻撃位置へ向かう全経路点を行動範囲内に収める。既に射程内なら接近しない。それ以外の攻撃地点は到達可能なマス中心から「現在位置からの移動経路長→標的との距離→X→Y」の昇順で選ぶ。4方向探索の隣接順は右→下→左→上に固定し、同じ状態で同じ移動先・経路を得る。
6. 行動範囲は冒険者の移動位置を制限する。侵攻では、標的自体が中心から3マスを超えていても、範囲内の攻撃位置から実効射程に入れば攻撃可能。防衛の既存の追撃・帰還規則は変更しない。
7. 標的死亡・離脱等で有効候補がなくなったら、経路の行軍点へ戻って次の進軍目標へ進む。帰る先は侵入口の初期配置マスではない。経路の終点に触れただけでは突破しない。

初期マップでは、全敵・設備を経路から接近・攻撃可能な位置へ配置する。通行不能・接近不能・到達不能な攻撃目標、空の経路、非連続の経路、同一ID、0以下の制限時間等は定義読込時に拒否し、プレイ中の行き詰まりにしない。

### 4.2 標的優先と技能

| プリセット | 候補内での優先 | 同順位 |
| --- | --- | --- |
| 近い敵（標準） | 現在位置からの距離が小さい | 生成順 |
| HPが低い敵 | 現在HPが小さい | 距離→生成順 |
| HPが高い敵 | 現在HPが大きい | 距離→生成順 |
| 設備優先 | 砲台・門・拠点を守備兵より先にする | 距離→生成順 |

- 設備優先も交戦可能な候補内に限る。遠い設備への優先指定で通行不能な追跡を始めない。
- 有効な標的は1回の攻撃動作の区切りまで保持する。死亡・射程外などで不成立になった場合は既存の取消・硬直・発射済み投射物の規則を使う。優先設定の変更は次の標的選択から反映する。
- 通常攻撃、自動技能の優先、実枠別CD、ULT待ち、非追尾投射物、状態異常、ダメージ計算、会心は既存規則を使う。手動発動は追加しない。
- 発射済み投射物は最初に衝突する相手へ命中する。設備優先は敵守備兵を貫通させる機能ではない。
- 回復・支援は現在位置から範囲内の有効な生存味方を選ぶ。回復はHP割合が低い相手→生成順。HP0者は通常回復しない。回復だけのために味方を遠くまで追いかけるAIは追加しない。

### 4.3 敵の役割

- **守備兵：** 初期守備位置を中心に警戒・局所追撃し、追撃を終えたら守備位置へ戻る。警戒範囲内で交戦可能な最も近い生存冒険者→生成順で標的を選ぶ。攻撃地点と経路の同順位も§4.1の順序を使う。初期案は警戒4、行動半径3、通常射程1.5マス、移速2マス/秒、通常攻撃間隔1秒。技能なし。
- **固定砲台：** 移動せず、射程4マス以内の最も近い生存冒険者を攻撃。同距離は生成順。通常攻撃間隔1.5秒、非追尾弾の速度6マス/秒。技能なし。
- **門・最終拠点：** 攻撃しない破壊目標。守備兵と別の構造物区分だが、通常攻撃・攻撃技能・会心の対象になる。通常回復の対象にはならない。
- 初期版では砲台・門・拠点の状態異常付与を無効とし、同じ技能の直接ダメージは有効。守備兵には既存の状態異常を適用する。構造物だから無条件に最低1ダメージを追加するような別計算は作らない。
- 守備兵・砲台とも標的は1攻撃の区切りまで保持する。固定ジョブ、挑発、被弾によるヘイト蓄積は導入しない。

## 5. 区画・勝敗・時間

- 3区画全体を1マッチとし、再挑戦ごとに試行IDを分ける。各区画に守備隊と1個の門または拠点を置く。増援はない。
- 区画1/2は守備兵・砲台・門の全撃破で突破。区画3は守備兵・砲台・最終拠点の全撃破で勝利。門だけを先に壊しても残敵がいれば戦闘は続く。
- 区画制限時間の初期案は各300秒の戦闘時間。一時停止・準備中は進まず、区画開始で区画経過時間だけ0秒へ戻す。CDや状態異常の期限が参照する通算戦闘時刻は区画間で戻さず、区画開始時の通算時刻との差で区画経過時間を得る。時間切れは敗北とし、曖昧な「進軍不能」の自動判定は設けない。
- 更新は既存と同じ20ms。個々のダメージ等は既存の固定順で反映する。各更新の処理後、次の順序で結果を1回確定する。

| 優先順位 | 条件 | 結果 |
| --- | --- | --- |
| 1 | 配置済みの生存冒険者が0名 | 敗北。控え・資源・発射済み弾が残っていても継続しない |
| 2 | 当該区画の全守備兵・全設備・門/拠点がHP0 | 区画1/2突破、区画3勝利 |
| 3 | 区画戦闘時間が制限以上 | 時間切れ敗北 |

同じ更新で全滅と拠点破壊が成立した場合は敗北。同じ更新で生存者を残して全撃破と時間切れが成立した場合は突破/勝利。終了後の弾・DOTで敗北を勝利に変えない。敗北区画を突破数に含めない。

## 6. 区画間・成長・マッチ資源

| 項目 | 規則案・初期値 |
| --- | --- |
| 開始資源 | 1000。区画ごとの再支給なし |
| 撃破資源 | 守備兵のみ `敵Lv × 2`。砲台・門・拠点は0 |
| 突破資源 | 区画番号 `k × 100`。最終区画も1回付与し、残資源は帰還で換金しない |
| Lv | マッチ開始Lv1、上限10。必要XP `125 + 75 × (現在Lv − 1)` |
| 突破LvXP | その時点までに1度でも配置した各冒険者へ50。HP0者も対象。未配置者なし、過去区画分の遡及なし、撃破LvXPなし |
| LvXP購入 | 準備中の生存・配置済み冒険者のみ。次Lvへの不足XPを1XP=資源2で全量購入。部分投入、上限後、資源不足では消費しない |
| Lv強化 | 既存の3候補から1つ選ぶ規則を使用。次区画の開始前に未選択を解決する。戦闘不能者の突破Lv上昇も既存規則どおり処理 |
| 復帰 | 準備中のみ。費用初期案 `25 × 当人の今回成功復帰番号n × 現在Lv`。HPは復帰後最大HPの10%をceil。待った区画数による増額なし |

- 通常突破では、生存者のHP・Lv・LvXP・一時強化・状態異常・技能CD進行・使用記録を引き継ぐ。無償全回復や通常/ULTの開幕状態再配布は行わない。準備中は通算戦闘時刻が止まり、残り2秒の異常は次区画でも残り2秒から進む。
- 次区画では敵・投射物を作り直し、味方の位置・行動中の標的・始動/硬直を準備状態へ戻す。開始時は新しい出撃マスが行軍開始位置となる。HP・強化・CDを初期化する操作とは分ける。
- 復帰はLvのみ保持し、LvXP・一時強化・状態異常等を既存規則どおりリセットする。通常技能ready、ULT待ち。本人の成功復帰回数と二重適用防止記録は区画間・同試行再開で保持。不成立では資源も回数も消費しない。nは当該試行内で本人が成功させた復帰の今回番号であり、敗北再挑戦ではマッチ開始snapshotの回数へ戻す。前試行で2回復帰していても、新試行の初復帰はn=1。
- HP0者へのLv購入は復帰後に行う。HP0者が突破によるLv強化を選択してもHP0を維持し、復帰を代替しない。復帰では本人の未選択Lv強化と保存済み候補も一緒に破棄し、古い候補が残って開始不能になる状態を防ぐ。消費済み候補乱数を復帰操作だけで巻き戻したり、代替候補を配り直したりしない。画面には復帰で失う変動値を示し、「復帰→Lv購入→強化選択→配置確認」の順で準備できるようにする。
- 最終区画の突破XPは記録するが、勝利結果でLv購入やマッチ内強化選択はしない。残りのLvXP・未選択強化は恒久成長へ換算せず帰還で終了する。
- 一度も購入しない場合、3区画の自然LvXPは最大150で、Lv2・残25XP。Lv10到達をこの試作の体験目標にはしない。区画1後にLv2へ上げるなら不足75XP=資源150、区画2後なら不足25XP=資源50。

## 7. 帰還報酬・恒久成長

区画報酬はマッチ内の値。恒久報酬、RankXP、衰弱、次回効果の消費は、勝利または敗北後に帰還する時点で一括して1回だけ確定する。再挑戦前の敗北結果では精算しない。

- 参加者は当該試行で1度でも配置した冒険者。戦闘不能者もRankXP対象。編成のみ・未配置者は対象外。
- `T`はステージの報酬用Rank、`r`は参加者の開始時冒険者Rank平均、`d=T−r`。全参加者に共通の補正を使う。現在Rankの変化を先取りしない。
- RankXPの調整初期案は `c=clamp(1+0.05d, 0.25, 2)`、勝利1名 `floor((100+20T)c)`、敗北1名 `floor(0.25(100+20T)c × 突破区画数/3)`。参加者0なら0。敗北は最終試行の突破数を用いる。
- 例：T=1、開始Rank平均1なら、勝利で各120XP、区画1で敗北0、区画2で敗北10、区画3で敗北20。恒久Rank必要XPは既存の `100+25×(現在Rank−1)`。
- 拠点資源の調整初期案は勝利300、敗北 `100 × 突破区画数`。勝利300に途中区画分を重ねて加算しない。残ったマッチ資源は持ち出さない。
- 勝利時は既存生成器で武器1個をギルド在庫へ。生成済み結果と生成乱数を精算と同じ保存単位で確定する。
- この試作はステージ別初回報酬を追加しない。既存のプレイヤー全体の初回クリア報酬（再選の札・祓いの雫）は全モード通算1回。既に受領したセーブでは侵攻で再支給しない。新規プロフィールで侵攻が初勝利なら既存の1回分を支給する。
- 終了時のHP0/生存/非出撃を記録してから衰弱を判定する。HP0終了者は衰弱+1、生存・非出撃者は解除。生存・非出撃者の最大HP50%回復後、HP0者を最後にHP1へ戻す。最大HP制限・丸めは既存規則を使う。非編成者も非出撃として扱う。
- 次回効果は実配置者のみ既存規則に従って最終帰還で消費する。未出撃者の分を消費しない。Rank上昇ごとのイベントと履歴は既存の仕組みへ接続する。

これらの係数・資源・武器報酬はローカル検証用の案。防衛との所要時間当たりの効率は未検証で、正式バランスやADR4 Q301〜305/Q337への回答としては扱わない。

## 9. 保存・互換性・処理の境界

- 陣営（味方/敵）と役割（侵攻冒険者/守備兵/砲台/目標物）を別に扱う。進軍させるために味方を敵フラグへ変更しない。
- モード、ステージID、区画番号、通算戦闘時刻と区画開始通算時刻、遠征編成、参加履歴、現在位置と指定出撃マス、各HP/CD/状態、資源、用途別乱数、match/attempt/event/cast ID、目標物状態を保存対象に含める。残り時間は保存した区画時刻と固定定義から復元できるようにする。
- 持込構成と開始時定義実体/hashを固定する。次の出撃でのみ新定義を使い、読込・再挑戦で生成済み武器や技能割当を引き直さない。
- 強制終了が戦闘中なら、**同じ試行の現在区画の開始snapshot**から復元する。途中の撃破資源・HP損失・CD・残時間・乱数等は開始点へ戻し、途中利益を二重反映しない。snapshotには戦闘乱数だけでなく、その試行が消費するLv強化候補抽選の乱数状態（現実装のprofile.GrowthRngに相当）も含め、一緒に復元・保存する。マッチ進行中に他の恒久成長操作でその乱数を消費しない。
- 準備中は購入・復帰・配置・強化選択を確定ごとに保存し、確定済みの準備をやり直させない。勝敗確定後の再開は結果画面。区画突破と報酬・XP・次準備への遷移は1保存単位とする。
- 敗北後の再挑戦は**最初の区画開始直前のマッチ開始snapshot**へ戻し、新しい試行IDを付ける。進んだ区画や購入結果を前試行から混ぜない。開始時定義・持込・初期配置・開始前支出・復帰回数・戦闘とLv候補抽選の乱数状態を同じ状態へ戻す。同じ操作列なら同じLv候補・戦況を得る。武器報酬の生成乱数は区画内で消費せず、帰還TXで別に確定する。
- 帰還処理は資源、武器生成結果、RankXP、Rankイベント、HP/衰弱、次回効果消費、履歴、マッチ終了を単一TXで確定する。同じ操作ID/内容は同じ応答、内容違いは拒否。確定後に応答を失っても二重支給しない。
- 本仕様案の実装では、プロフィールとマッチの保存文書形式2を用い、モード未指定の旧形式1は防衛として読み込む。旧防衛の戦闘処理版・定義hashの検証規則を維持し、旧進行中マッチを最後まで再開可能にする。侵攻は独立したルール識別子/版を持つ。旧hashを新しい既定値込みで再計算して上書きしない。
- SQLiteのテーブル構造変更は必須とせず、JSON文書の形式移行も移行作業として扱う。既存DBを変更する前にSQLite Backup APIでバックアップし、プロフィールとマッチを一括移行する。ID・資源・生成武器・履歴・受付済み操作を保持する。
- 将来版・未対応ルール・破損データは説明付きで拒否し、元DBを変更しない。移行失敗時は旧DBを読める状態へ戻す。版番号を上げるだけで旧マッチの互換を切らない。
- 検証はテスト用DBと既存セーブのコピーで行う。ユーザーの実データで勝敗・移行の破壊試験を行わない。

**今回選ばない案：** 各冒険者への自由移動命令は操作と経路制御が増えるため初期対象外。モンスター陣営の召喚は今回の「育てた冒険者」という指定に合わない。自動隊列維持は速度差と交戦の同期が複雑になるため、まず初期位置と各自の進軍を試す。区画突破の全回復・CDリセットは既存の資源・復帰・持続状態の意味を変えるため採らない。

**残るリスク：** 速度差で後衛が先行する、遠距離が有利になる、回復範囲から離れる、短時間攻略が防衛より報酬効率で有利になる可能性。これらは発生済みの不具合ではない。最初の試作で記録し、数値調整は本案の初期値として扱う。自由指示や隊列AIが必要になる設計変更は、証拠を持ってOrient/Decideへ戻す。

既存Deferred Solution Queueは存在しない。今回、具体的な採用予定と再検討契機のない追加機能を新規キューへ登録しない。
