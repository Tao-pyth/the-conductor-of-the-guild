# 派遣・素材納品・金貨拠出 — 0.5.0-dev ローカル実装契約

2026-10-26。正式baseline v0.3.0、対象0.5.0-dev/Windows 0.5.0.0。ユーザーの実装依頼に基づき、派遣・素材・3種納品・金貨拠出をゲーム内で操作できる状態にし、既存の0.4.0-dev改修を保持してローカルWindows ZIPまで検証する。

## Scope / Chosen Approach

- 派遣は任意の同時1組、1〜6名。次の新規防衛/侵攻へ出撃確定した時点で出発、同マッチ帰還精算まで拘束する。生存/出撃可能者を最低1名残す。予約中は編集/取消可能。
- 成功率はfloor(20+40R+20W+20B)、上限100%。R=min(1,Σmin(本人Rank/推奨Rank,1)/目安人数)、W/Bは現在装備武器種/現在所持加護IDの条件充足率。重複種類と加護I〜IIIを追加点にしない。出発時の定義・メンバー・率・1回抽選結果を保存し、再起動/再挑戦/閲覧で変えない。
- 主戦闘勝敗/突破率は派遣成果へ影響しない。派遣成功は規定素材満額、派遣失敗は規定の1/4(個別切捨て、合計0なら主素材1個)を持帰る。成功素材は人数nに対し基礎量×(n+1)/2を切捨て。派遣者のHP/衰弱を維持し、次回出撃限定効果を消費しない。
- 派遣RankXPは本人Rankと派遣推奨RankTに対する既存勝利基準floor((100+20T)×Clamp(1+0.05(T-r),0.25,2)×係数)。係数は派遣成功1/4・失敗1/8。主戦闘参加者平均へ含めず、帰還時に一度適用し既存Rankイベントへ接続。マッチLvXPなし。
- 共通素材はwood木材/ore鉱石/herb薬草/crystal魔力結晶。共有倉庫、非負整数、容量制限なし。防衛/侵攻の完全突破基礎量は各8/6/6/4。最終試行の突破済み割合を各素材へ掛け切捨て、勝利時は完全量。帰還時のみ受領、再挑戦分を合算しない。
- 派遣3件: recovery廃材回収(T1/目安2/槌・剣/剛力・剛健/木材8鉱石4)、patrol街道の補給巡回(T3/目安3/弓・槍/活力・剛健/薬草8木材4)、survey遺構の資材調査(T5/目安2/杖・槌/剛力・活力/結晶4鉱石4)。加護は現tech IDへ明示対応。新カタログは戦闘ContentBundleから分離し旧定義hashを変えない。
- 納品13件: 4勢力(C宮廷/M魔法協会/K騎士団/T住民)の関係納品各1、既存5武器種の装備納品各1、4素材の金銭納品各1。必要素材/報酬はデータ表で固定し、装備実物は掲示時生成/保存して公開、取消/再起動で再生成しない。素材を満たせば即納品、消費/報酬/関係を一括確定。同コマンド再送は重複なし。
- 関係納品は少額5金貨+協力実績5、金銭納品は素材4個(木/鉱/薬)または結晶2個に対し20/30/15/35金貨。関係材料は2〜6個、装備材料は武器ごとの20〜40個程度をカタログで公開する。既存購入1000・直接マッチ報酬・装備所有権を保持し、納品装備は未譲渡ギルド品→既存Rank譲渡。防具/装飾自体の新規装備システムは対象外。
- 関係は協力実績-100〜100。既存ストーリー本体は未実装のため、本機能では日常協力の値/状態を保存・表示する。重大対立フラグがある状態では納品で原因を解除せず修復中表示を維持する。女王の好感度は追加しない。
- 通貨名は金貨、ギルド/任務残高を分離。任務1000+拠出C(非負整数、所持金以内、初期0/上限なし)。出撃確定時にCを一度だけ徴収。終了残金は全額破棄し契約報酬のみギルドへ加算。再挑戦は初開戦直前の配置/残金へ戻り再徴収/再配布しない。準備開始後の途中取消は追加しない。
- 既存全所有者=戦闘unit前提を維持し派遣者を削除しない。防衛配置/侵攻編成/強化/復帰/標的操作等の実コマンドで拘束者を拒否し、UIにも派遣中を明示。既存控え回復を派遣へ適用しない。
- プロフィール/マッチ文書形式3、SQLite schema1。旧1/2は変更前検証→バックアップ→同時移行。旧進行中マッチは新経済無効のまま再開/再挑戦/精算、新規から適用。未知/破損保存は書込前拒否。

## Work Units

ECO-01 純粋成功率/成果/カタログ、ECO-02 永続状態・互換・再送、ECO-03 派遣/拠出/素材/納品/精算のApplication、ECO-04 Godot画面/文言/実体試験、ECO-05 回帰/説明/版/ZIP。Issue登録は必須とせず本書/Obsidianで追跡する。

## Acceptance Criteria / Test Requirements

- AC01: 3要素の式/上限/整数境界/重複/低Rank追加/高Rank1人制限を検証。表示と実抽選が同じ算定を使用。
- AC02: 1〜6名の予約/取消、全員派遣拒否、派遣者の両モード出撃拒否。武器/加護変更後の事前表示と出発固定が一致。
- AC03: 主戦闘勝利/敗北×派遣成功/失敗の4組で素材/XP/拘束解除を一度精算。派遣HP/衰弱/次回効果を維持し主戦闘XP係数へ混ぜない。
- AC04: 戦闘素材は最終試行だけ。再挑戦/途中再開/同CommandIdで派遣結果・徴収・素材・納品・装備/関係が重複しない。表示照会はRNG/保存/所持金/在庫不変。
- AC05: 3種納品が拠点UIから完了でき、条件不足/非法入力時は消費なし。装備実物プレビューと取得物が一致し既存譲渡で装備可能。重大対立原因フラグを消さない。
- AC06: 任務1000+C/G−C、初期0/所持額全額/不足/負数/巨大整数を検証。残金返還なし。再挑戦時再徴収なし。拠出0で通常出撃可能。
- AC07: 旧1/2の拠点/進行中保存をバックアップ付き移行。装備/定義hash/旧防衛/侵攻/履歴/残高を保持、将来/破損/混在はDB変更前拒否。原子的保存の前後故障も検証。
- AC08: 既存207件以上の全回帰と追加必要テストが失敗/skip0。Debug/Release/ExportReleaseビルドの警告/エラー0。
- AC09: Godotの派遣/成功率プレビュー/素材と納品/拠出/派遣中候補/帰還結果を1920×1080、1280×720、1000×640の実画面で確認し画像・ログ・実寸を保存。実ユーザーDBを使わない。
- AC10: 0.5.0-devの版/説明/CHANGELOG/英語+初心者向け日本語リリース説明、新Windows ZIP/SHA256を別保存先に作り、再展開したSDK不要実体で主要操作/保存再開/既存両モードを確認。旧ZIPを保持。

### 後続依頼によるGitHubソース反映（2026-10-26）

上表はローカル実装時の契約として保持する。その完了後のユーザー依頼「GitHubへの更新を」と反映範囲の回答により、0.5.0-dev実装と必要な関連文書のCommit/Pushおよびリモートソースの照合をrequiredとして追加する。前提の0.4.0-dev改修を含み、独立したストーリー・別UI提案・ADR等は手元に保持する。コミット対象だけで全テストとReleaseビルドを確認し、mainへ反映する。PRは必須運用がなく直接反映とする。Tag/GitHub Release/ZIP公開/Issue登録は引き続きnot-requiredで、正式baseline v0.3.0は変えない。

## Non-Scope / Rejected Alternatives / Risks

物語全編のゲーム化、既存技能/加護の全件収録、装備スロット拡張、敵性能/既存直接報酬の再調整、DSQ-001の高Rank設計、実ユーザーDBでの試験、既存未コミット作業の巻戻し、外部公開は対象外。派遣を主戦闘敗北/進度で減額する案、任務残金返還、再挑戦による派遣再抽選を採らない。

人数・任務と納品数量は初期調整値。主戦闘即敗北でも派遣を精算できる指定は維持し、素材/派遣成功率/操作時間込みの経済は今後の調整対象とする。新しい関係値は物語選択の実装完了を意味しない。
