# v0.4.0-dev — 防衛判定とプレイヤーの判断材料

作成日：2026-10-25。正式baseline：v0.3.0。対象：ローカル開発版0.4.0-dev（Windows数値版0.4.0.0）。実装・検証状況は[検証記録](player_decision_support_verification_v0.4.0.md)、完了条件は[ローカル契約](release_contract_v0.4.0.md)を参照する。

## 目的と範囲

防衛で敵が移動途中の射程接触を飛び越える問題を修正し、成長対象・能力・技能・費用・配置範囲・次の敵を、確定前にゲーム内で確認できるようにする。追加の成長確認ダイアログ、総合戦力、予測DPS、自動編成は設けない。

敵のHP/速度/火力/射程、報酬、経験値、復帰、帰還回復、侵攻の成長タイミングは変更しない。現在標的・戦闘中の新しい範囲表示・精算サマリー・新しい戦闘ログも今回の対象外。固定ジョブ、技能・加護・ステージ、台帳全件収録を追加しない。

## 1. 新しい防衛と旧マッチ

- 新規防衛は`defense-v2`。冒険者を攻撃する敵の20ms移動を経路の辺ごとに調べ、射程に最初に接触した辺で停止する。接触候補の順序はentry、停止点からの対象距離²、生成順で固定する。
- 既存の決定的な`SegmentCircleEntry`を再利用し、停止点が実際に射程内であることを分数で確認する。射程や更新間隔を広げる修正は行わない。数学的に厳密な接触時刻や、停止座標の1e-6精度を新たに保証しない。
- 移動時に即ダメージを与えず、通常の行動選択、200ms始動、硬直、攻撃間隔、命中時の対象確認を使う。終点到達と接触が同時なら防衛対象への到達を優先する。
- 旧保存のnull/`defense-v1`は旧判定を継続する。準備画面に旧判定であることを示し、現在マッチ・再挑戦を途中でv2へ変えない。修正は次の新規防衛から適用される。
- `invasion-v1`の進軍と判定は変更しない。敵が接触を検出して攻撃する機会が増えるため、新規防衛の勝敗・被害・時間が旧版と完全一致する条件は置かない。
- Current/MatchStart/WaveStartのルールを保持する。nullとdefense-v1は同じ旧版として扱い、既知でも異なるルールが混在する保存や未知のルールは書込前に拒否する。

## 2. 成長対象の事前表示

拠点の既存4種類の成長ボタンの直前に、次の対象の名前、今回のイベントRank、現在Rank、装備、加護、今回を含む未処理件数、選択後取消不可の説明を置く。通常の閲覧で選択している冒険者を成長対象へ付け替えない。

例：「次の成長：アオイ — Rank2のイベント／現在Rank4」。複数回の成長を保留している場合も、今回使うイベントRankを示す。種別選択後に初めて対象が分かる流れを解消し、確認クリックは増やさない。

- 対象はSequence昇順の先頭。表示、CurrentEvent、選択済みロック、履歴も同じ取得処理を使う。
- 新UIは既存の`BeginEvent`へActorId=表示対象、TargetId=表示EventId、Value=種別を渡す。渡されたIDが先頭と違う場合は候補生成前に拒否し、何も消費せず対象を再表示する。
- 両IDを省略した従来の内部呼出しと、保存済みCommandIdの再送を維持する。新しいコマンドフィールドや保存形式を追加しない。
- 取得可能な通常加護がない、譲渡するギルド在庫がない、合成素材を満たさない等の利用不可理由を、選択前に表示する。
- 表示は候補やランダム結果を生成せず、未知合成や未実行のランダム結果を先に公開しない。開始済みイベントは保存した対象・種類・候補・定義で再開し、取得・譲渡・合成の見出しでも同じ対象を示す。

## 3. 能力・技能・費用

| 場所 | 算定の基準 | 表示する判断材料 |
| --- | --- | --- |
| 拠点・出撃先選択 | 次の出撃の参考値。現在定義、保存済み武器、恒久成長、加護、衰弱、次回効果、Lv1 | HP、衰弱、通常攻撃値、防御、攻撃間隔、移速、武器射程、技能、個人初配置費 |
| Wave/区画準備 | このマッチの実値。開始時固定定義、実ユニット、Lv強化等 | 上記の現在値、不足LvXP、購入費、到達Lv、利用可否と理由 |
| 詳細 | 基本5能力、加護、保存武器と実技能枠 | 基礎と実効の区別、効果・係数、対象、射程、CDと単位 |

- 攻撃値は敵の防御・会心適用前の参考値で、敵へ実際に与えるダメージや予測DPSではない。表示専用の戦闘式をGodot側へ作らず、Domain/Applicationの実算定を純粋な照会へ最小限抽出して共有する。
- 最大HPなどの整数確定は戦闘へ合わせる。例：素HP190×衰弱0.95なら戦闘最大HPはfloorした180であり、表示だけ181へ切り上げない。戦闘値自体の変更は行わない。
- 武器は生成済みの威力・間隔・射程・SkillIdsを参照する。閲覧で再生成しない。同SkillIDのS1/S2も別の実枠として示す。空枠には存在しないCDを作らない。
- 技能は名前だけでなく、攻撃/回復/状態効果、係数、対象種別、固有射程、CDを日本語と単位で説明する。射程に加えて警戒・行動範囲等の条件があることを示す。
- 整数HP・Rank・XP・費用は確定整数のまま。分数値は秒・マス・%の表示単位へ変換してから小数第2位へ数学的ceilする。負数例は−1.234→−1.23。表示値を戦闘へ書き戻さない。
- Lv10は「購入0円」ではなく「上限」。現在の不足XP、費用、到達Lv、利用できない理由を一緒に示す。HP0者の購入は侵攻不可・防衛可という現行差を保持する。

### モード別の出撃

- **防衛：** 所有冒険者を比較する一覧から「防衛へ出撃」。事前の固定1〜10名チェックを設けず、全所有者がWave間の配置候補であることと、同時配置上限10を説明する。
- **侵攻：** 従来どおり1〜10名の固定遠征編成。詳細を見る操作で編成チェックを変更しない。個人の初配置費用と、選んだ全員を初配置した場合の参考合計・開始資源を示す。
- 参考合計は出撃時に徴収する額ではない。控えを残せるため、合計が開始資源を超えても侵攻出撃は禁止しない。実際の配置で既存どおり徴収・不足拒否を行う。

## 4. 準備中の範囲と次の敵

選択した1名の範囲表示は準備画面で初回ONとし、画面内の切替で非表示にできる。設定を新たに永続保存せず、戦闘中・一時停止中の新しい範囲表示は追加しない。

| 範囲 | 中心・距離 | 意味 |
| --- | --- | --- |
| 警戒 | 現在位置、4マス | 標的選択の条件の一つ |
| 行動 | 防衛の指定アンカー／侵攻準備の出撃位置、3マス | 移動できる局所範囲 |
| 通常攻撃 | 現在位置、実効武器射程 | 別の条件も満たしたときに通常攻撃できる距離 |
| 技能 | 現在位置、選択した実枠の固有射程 | 効果と対象に応じた距離。回復は生存する負傷味方が対象 |

線種・ラベル・距離・凡例で範囲を区別し、射程円を「必ず攻撃する領域」と呼ばない。回復円を行動半径3との交差へ切り詰めない。実位置とアンカーが違う場合は、それぞれの中心を使う。

未配置者は有効な配置候補マスへhoverしたときだけ仮配置の円を出し、未使用座標(0,0)へ円を出さない。配置済み者の仮配置表示は再配置モード中のみ。無効マスは有効候補として描かない。hoverや切替で配置・費用・乱数・保存を変えない。侵攻には「開始位置の目安。合流・進軍・交戦で中心が変わる」と説明する。

次に始める1Waveについて敵数・1体HP・冒険者を攻撃するかを予告する。HPは実生成と同じ`max(1,floor(EnemyHp))`。侵攻は次区画の守備兵・砲台・門/核の数と制限時間を示す。固定されたマッチ定義を参照し、最終結果には架空の次Waveを出さない。

UIは1280×720と最小設定1000×640で操作確認する。実際のclient・viewport・PNG寸法を記録し、スクロール後も対象・数値・凡例・主要ボタンが読めること、重要情報がhoverだけに依存しないこと、追加コントロールへフォーカスで到達できることを確認する。
